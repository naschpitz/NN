Convolution Kernel Pipeline

Convolution on the GPU is computed via im2col + GEMM instead of direct convolution kernels. The im2col transformation rearranges the input so that convolution becomes a matrix multiplication — see Math: im2col + GEMM for the full explanation. The tables below show exactly which kernels run for each logical operation per conv layer:

Forward Pass (per conv layer)

StepLogical OperationKernelsWhat It Does
1 Compute convolution output im2col → gemm_conv Rearranges input patches into a column matrix, then computes Output = Filters × im2col(Input) + Bias. Each row of the Filters matrix is one filter flattened; each column of the im2col matrix is one input patch. The matrix product computes all filters at all spatial positions in one operation.

Backward Pass (per conv layer)

StepLogical OperationKernelsWhat It Does
1 Compute filter gradients im2col → gemm_dFilters Computes dFilters = dOut × im2col(Input)T. Each element of dFilters is the dot product of one row of dOut (gradient at each spatial position for filter f) and one column of im2colT (input values seen by that filter element). B is transposed because im2col is stored as (rows, cols) but we need the input patches as rows, not columns.
2 Compute bias gradients calculate_dCost_dBiases Sums dOut over all spatial positions per filter: dBias[f] = Σ dOut[f, o_h, o_w]. Uses parallel reduction (one work-group per filter).
3 Compute input gradients gemm_dInput → col2im Computes dInput_cols = FiltersT × dOut, then scatters back to input shape. A is transposed because Filters are stored as (numFilters, filterVolume) but we need (filterVolume, numFilters) to project the output gradients back into the input space. The col2im kernel reverses the im2col rearrangement, accumulating overlapping patch contributions.
Why transpose variants instead of actually transposing matrices? Transposing a large matrix on GPU is itself an expensive memory operation. Instead, gemm_dInput and gemm_dFilters read the matrix elements in transposed order during the tile-loading phase — A[col][row] instead of A[row][col]. Same data, different indexing, zero extra memory or kernel launches.

GEMM Kernels

CNN_GEMM.cpp.cl

Tiled General Matrix Multiply kernels. The three tiled variants use the same tiled algorithm with local memory — only the indexing into A or B differs for transpose variants. A fourth variant, gemm_dFilters_kpar, uses a K-parallel reduction for the split-K-bound dFilters case where the tiled approach cannot fill the GPU (see below).

Tiled dispatch: 2D global work size (ceil(N/TILE)*TILE, ceil(M/TILE)*TILE), local (TILE, TILE).

KernelMatrix OperationConvolution Equivalent
gemm_conv C = A × B + bias Forward: compute all filter outputs at all spatial positions
gemm_dFilters C = A × BT Backward: compute how much each filter weight contributed to the error (dFilters)
gemm_dInput C = AT × B Backward: project output error back into input space (dInput)
gemm_dFilters_kpar C = A × BT (K-parallel reduction) Backward: filter gradients for split-K-bound layers (small M×N output, large K) where tiled GEMM underfills the GPU. Also used for 1×1 residual projection backward

Arguments (gemm)

ArgumentTypeDescription
Aglobal TYPE*Matrix A (filters)
Bglobal TYPE*Matrix B (im2col output)
Cglobal TYPE*Output matrix (activations)
biasglobal TYPE*Bias vector (length M)
offsetA/B/CulongByte offsets into each buffer
offsetBiasulongOffset into bias buffer
M, N, KulongMatrix dimensions: A is (M,K), B is (K,N), C is (M,N)

The transpose variants (gemm_dInput, gemm_dFilters) have the same arguments except without bias and offsetBias. The gemm_dFilters_kpar variant takes (A, B, C, offsetA, offsetB, offsetC, M, N, K) — no bias argument.

K-Parallel dFilters Variant

The tiled GEMM launches one work-group per output tile, so it only fills the GPU when the output matrix M×N is large enough. The dFilters operation (C = dOut × im2colT) has M=numFilters, N=k²·Cin, K=outH·outW. For early, high-resolution layers M×N is small (e.g. 32×27 = 864 elements = 4 tiles at TILE=16) while K is huge — the GPU sits nearly idle because the parallelism lives entirely in the K dimension, which the tiled output-parallel approach cannot exploit.

gemm_dFilters_kpar flips the parallelism axis: one work-group per output element (256 work-items cooperatively striding over K), tree-reducing partial sums in a local TYPE partials[256] array. This turns 864 outputs into 864 work-groups instead of 4 — a ~200× parallelism gain for the worst case. Each element is written once per sample (full assignment, =), matching the two-buffer accumulate pattern used by the tiled variant.

Device-aware dispatch. GPUKernelBuilder selects the variant per layer at kernel-build time, based on whether the tiled approach can fill the GPU: 
tiledGroups = ceil(M / 16) * ceil(N / 16)
if (tiledGroups < computeUnits * 4) → gemm_dFilters_kpar   // tiled can't fill the GPU
else                                → gemm_dFilters        // tiled is well-occupied
computeUnits is queried at runtime via getDeviceInfo<CL_DEVICE_MAX_COMPUTE_UNITS>() (exposed by the OpenCLWrapper submodule), so the threshold auto-adapts to the device. The factor 4 is a dimensionless occupancy target (work-groups per compute unit). On a 128-SM GPU this routes the small-output layers to the kpar path and the large-output layers to the tiled path — empirically cutting the dominant dFilters layer from 33% to under 3% of per-sample time.

im2col / col2im Kernels

CNN_Im2Col.cpp.cl

im2col

Rearranges input patches into a column matrix for GEMM-based convolution. One work-item per output element. Dispatch: 1D, nElements = C_in × K_H × K_W × O_H × O_W.

ArgumentTypeDescription
inputglobal TYPE*Input activation buffer
colglobal TYPE*Output column matrix (cnn_im2col)
inputOffsetulongOffset into input buffer
C, H, WulongInput tensor dimensions
kH, kWulongFilter dimensions
strideY, strideXulongConvolution strides
padY, padXulongPadding amounts
outH, outWulongOutput spatial dimensions

col2im

Inverse of im2col — scatters column matrix back to input tensor shape, accumulating overlapping contributions. Used during backpropagation to convert dInput from column layout back to tensor layout. One work-item per input element (avoids float atomics). Dispatch: 1D, nElements = C × H × W.

The gradient buffer must be zeroed before calling col2im, since it accumulates contributions from overlapping patches.

Arguments are the same as im2col, except col is the input (column data) and output is the gradient buffer being written to.
